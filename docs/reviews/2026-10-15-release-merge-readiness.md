# 新版功能合并与发布边界

本次整合 `codex/production-login-compat` 相对于 `main` 的桌面/H5 画廊、设备分流、Node 兼容接口、拾光助手及 Markdown 渲染。用户授权提交、推送和合并；本次没有切换线上 release、重启生产或替换业务数据。

## 合并前修复

- 移除整个仓库根目录的静态兜底和不再使用的 `@fastify/static`。只通过明确的前端目录路由提供 HTML、脚本和媒体，校验文件类型、隐藏路径及真实文件边界；部署配置、测试页和源代码不公开。
- 两端生产 API 不再在 HTTP 或网络失败后模拟签到、任务确认、兑换、上传、留言和故事保存成功。私密认证只接受服务端验证，不再接受演示密码；私密笔记和文件不回读共享浏览器缓存。
- 签到状态从真实余额接口读取，并适配 `checked_in_today`、`streak_days`、`last_checkin`。余额 0 原样保留，读取失败不复用其他账号的缓存。
- 私密下载固定使用根路径的受控下载接口，并转义链接属性。桌面登录的跳转目标复用站内路径校验。
- H5 私密锁定立即隐藏和清理正文，作废在途认证与列表请求，避免迟到响应重新展示内容。
- 普通退出登录保留后端 302 到登录 HTML 的兼容契约；私密退出检查真实 JSON 结果，网络或权限失败不伪报服务端已退出。
- 修复两组前端测试依赖进程工作目录的问题，新增真实脚本、DOM、HTTP 和文件访问边界回归。
- 迁移测试自行生成虚构账号、商品和任务资料，不再依赖本机未入库的账号配置；首次 Linux CI 揭示的干净环境缺口据此修复，不上传个人配置来满足测试。

## 验证方式

本地执行 `npm run check`、`npm test`；新增 GitHub Actions 在 Ubuntu / Node 22.23.3 中执行 `npm ci`、语法检查和完整测试。以对应提交的实际日志及 PR checks 为最终结果。

本次修复后本地全量结果：212 项中 210 项通过、2 项按设计跳过、0 项失败；33 个后端 JS 文件语法检查及两端前端脚本语法检查通过。独立审查对最新 16 项定向检查全部通过，源码审查放行；Linux CI 结果另见 PR。

完整测试默认跳过需要显式开启的常驻服务检查，以及未随源码提交的完整医疗语料检查；单元及集成测试使用隔离资料和临时数据库，不调用收费模型。

独立审查覆盖私密认证、业务失败、签到字段、下载路径、跳转和 H5 锁定。Windows 本地检查、Linux CI 与真实生产/设备验收是不同证据，不能互相替代。

## 部署范围

部署新版页面时须成组包含 `desktop/`、`h5/`、对应的 `assets/`、`index.html`、`home.html` 及 Node 服务源码，并在 Linux 使用配套 `server/package.json` / `package-lock.json` 安装运行依赖。测试、设计稿和文档可以版本管理，但不应公开提供静态访问。

以下不随业务发布同步：本地 DB/WAL/SHM、`node_modules`、用户上传、密钥、云账户记录、截图、旧备份、完整医疗语料及本地评测产物。保留生产 DB 和 uploads 的持久化路径、现有 SESSION_SECRET、权限和 Nginx 内部下载映射。

医疗检索代码是仅监听本机的独立调试工具，不在主应用注册，不增加公网医疗服务，不代表已接入向量 API 或具备医疗回答能力。

实际部署仍需按环境评估报告执行协调的 release 切换、生产健康/登录/下载/上传及真实设备验收，并准备成组回滚；合并 main 不等于已部署上线。
