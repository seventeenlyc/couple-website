# 设备授权：已实施规则与运维

更新：2026-09-05。此文档取代早期设计稿中的首次绑定码、双人审批等规则。

## 实际使用

1. 打开 `https://lyczwc520.site/`，会进入原有手账本样式的登录页。线上继续使用双方称呼验证；设备校验在后台执行。
2. 每个账号的首次成功登录自动绑定当前浏览器；只有一个并发请求可以获得首次绑定资格。
3. “拾柒”（线上内部 ID `shiqi`）为管理员。登录后页面右下方提供“安全与设备”，也可直接访问 `/device-access.php`。
4. 同一账号其他浏览器登录后进入等待页，显示 8 位核对码。管理员在自己已授权的浏览器输入该码批准；新浏览器自动领取登录会话。
5. 管理员可批准、拒绝和撤销双方的设备。另一账号可以查看自己的等待/授权状态，但不能查看管理列表或修改授权。
6. 普通退出保留设备授权；撤销后，旧会话下一次访问即被拒绝。撤销最后一台设备不会重新开放首次自动绑定。
7. 授权有效期 180 天，待授权申请有效期 10 分钟。清除 Cookie、换浏览器或授权到期后需重新审批。
8. 被拒绝、撤销或到期的旧浏览器凭证不会自动重新申请；清除本站 Cookie 后可重新登录申请，或由服务器恢复指定账号。

首次自动绑定属于用户选择的便捷规则：它信任第一个持有正确登录凭据的来访者，不验证物理身份。应由双方各自在常用浏览器完成首次登录。已存在的历史会话不会自动获得授权。

## 保护机制

- 每个账号单独使用一个 `__Host-couple_device_*` Cookie，256 位随机秘密，Secure、HttpOnly、SameSite=Strict；服务器只存摘要。
- 会话同时绑定成员身份及授权 ID，每次业务访问检查有效授权。不同账号的设备凭证不能混用。
- Nginx 将非公开请求交给 `device-gateway.php`。公开入口为通用登录页、设备页、登录/CSRF/设备接口及静态公共资源；设备接口内部单独检查操作权限。
- 共享图片和页面经过校验后由 Nginx internal 文件入口发送；私密文件额外验证私密空间认证及成员归属。支持线上原有 `/uploads/shiqi/`、`/uploads/shisan/` 和 `/uploads/private/成员/` 路径。
- data、运维脚本等不能通过统一入口读取。API 原有业务权限校验继续保留。
- 文件响应使用 private/no-store。授权撤销不能收回已经下载或缓存的内容，也不能阻止已控制授权浏览器的攻击者。
- 服务器使用独立锁文件和原子替换写入授权状态；数据丢失或损坏时拒绝访问，不能自动创建空白白名单。
- 登录限流按来源 IP 保存在服务端：15 分钟内最多 30 次请求。有效待审批申请每账号最多 5 条、全站最多 20 条；核对码错误 5 次使申请作废。
- 浏览器名称、IP 只用于辅助核对；管理员必须通过可信沟通确认申请人。

## 存储与恢复

线上状态文件：`/www/wwwroot/.couple-device-state/lyczwc520.site/state.json`。目录权限 0700、文件 0600，由 PHP 运行用户 www 读写；它在站点根目录外，站点专用 FastCGI 配置允许访问该目录。

`bound` 字段永久记录账号是否已完成首次绑定，普通撤销不会删除该记录。设备记录保留授权者、状态和时间；过期非活跃记录在后续登录时清理。不新增单独的持续写入审计日志服务。

所有管理员浏览器均不可用时，只能从服务器执行：

```sh
cd /www/wwwroot/lyczwc520.site
/www/server/php/82/bin/php tools/device-admin.php recover shiqi
```

这会撤销该账号所有设备并重新开放该账号首次绑定。执行后应立即清除常用浏览器的本站 Cookie，重新登录完成绑定。恢复其他成员时将账号 ID 换为 `shisan`。恢复操作不对公网开放。

`init` 只用于首次安装，已有状态文件时拒绝重置。禁止删除状态文件或把测试状态覆盖到线上。

代码与配置备份：`/www/backup/codex-device-auth-20260905-144713`，约 1MB。用户照片、业务数据和站点账号配置未被备份脚本改写。

## 维护注意事项

不要只回滚登录接口而保留其他部分，也不要把 Nginx 恢复为公开静态文件放行。出现故障时先通过服务器恢复或使用维护页面，保留访问限制。

HTML 中公共 API 脚本已增加版本号，避免缓存旧脚本导致管理员入口不出现。若管理员入口未显示，可直接打开 `/device-access.php`。
