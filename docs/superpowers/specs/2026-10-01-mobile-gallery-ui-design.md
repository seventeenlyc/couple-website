# 移动端画廊式情侣生活应用：UI 与交互设计规范

日期：2026-10-01  
版本：1.0  
状态：设计初稿，待评审；不代表页面、接口或原型已经实现。  
交付范围：主题、设计变量、信息架构、页面、组件、交互、异常状态、设计工具与验收标准。本文不包含产品代码修改。

## 1. 设计依据与已确定方向

### 1.1 用户已确定的方向

- 更换原有手账风，采用现代画廊风。
- 主要为移动端设计，具有手机 App 的导航与操作体验。
- 首页避免仪表盘感，不采用签到、积分、待办、未读数量、纪念日多卡片汇总。
- 照片、文字和共同生活是视觉主体，功能通过明确入口访问。
- 本轮只编写设计文档，不修改产品代码。

### 1.2 产品定位

为固定两名成员提供一个持续积累共同生活的私人空间。打开时可以看见一段回忆、读到一封来信，也能方便地上传照片、完成任务、兑换礼物。

主题工作名：**「我们之间 · 生活画廊」**。这是设计表达，不强制替换站点名称或现有账号称呼。

主题关键词：亲密、克制、真实、可停留、易操作。

默认方案为浅色主题。深色主题、原生安装包、推送通知、离线私密内容和复杂主题切换均不属于首轮范围。PWA 可作为独立后续项目，不作为 App 式 UI 的先决条件。

### 1.3 依据与优先级

1. 本次对话中用户最新确认的视觉、移动端和非仪表盘要求。
2. 当前页面与服务端实际业务约束。
3. `docs/project-improvement-requirements.md` 中功能、响应式、异常状态和可访问性要求。
4. `docs/project-improvement-design.md` 中共享组件和渐进改造方向。
5. `docs/device-authorization-operations.md`、相册目录选择设计与当前实现。

旧文档中的 PHP 运行时方案不是本次 UI 设计前提；工作区已存在 Node 后端。设备运维文档也包含历史规则，应以当前实现核对实际状态转换。此次未连接生产环境，不能据此断言线上版本。

本设计明确调整旧需求中“首页展示今日任务”等信息位置：任务与签到移至“心愿”，纪念信息集中在“我们”；首页只在确有相关事件时出现简短提醒。能力保留，展示层级改变。

## 2. 主题与视觉语法

### 2.1 画廊感如何实现

- 照片拥有足够面积，标题、日期、配文像展签一样排列在图片下方。
- 以版式、照片比例和章节间距产生节奏，不用重复卡片建立层次。
- 单张照片、双图和纯文字片段可以交替出现，排列由真实内容决定。
- 背景温暖但不做纸张纹理；装饰不遮挡照片主体。
- 酒红色用于操作和选中状态，让照片自身保留色彩主导权。

### 2.2 App 感如何实现

- 四个稳定的底部导航入口。
- 一级页保留导航，详情和编辑进入独立全屏层级。
- 返回保留列表位置、目录、筛选条件。
- 简短选择使用底部面板，复杂编辑使用全屏页面。
- 输入、上传、提交和错误恢复有连续、可理解的反馈。

### 2.3 禁止出现的视觉模式

- 首页积分余额、任务进度、签到天数、照片总数等统计卡片阵列。
- 大数字 KPI、饼图、进度环、四宫格工作台。
- 全站胶带、撕纸、邮票、倾斜卡片和手写英文大标题。
- 大面积粉紫渐变、玻璃面板、装饰性光晕或持续漂浮动画。
- 每个区块都套圆角白卡、加投影、再嵌套子卡片。
- 自动轮播、自动播放视频，以及迫使用户等动画结束才能操作的转场。
- 用 AI 虚构双方共同照片、聊天或纪念事件填充真实页面。

### 3.2 颜色使用约束

- 正文目标对比度至少 4.5:1；大字号文字和关键控件边界至少 3:1。
- 表单标签和错误说明不可仅靠浅灰色或颜色变化区分。
- 未读提示同时有文字，选中导航同时有图标或字重变化。
- 禁用按钮使用浅底、低强调文字和不可交互状态，但应在附近说明禁用原因。
- 图片上的文字若不能保证对比度，移至图外；图片查看器控制按钮使用稳定的实色底。
- 所有具体颜色组合在组件稿阶段复核，透明叠加和照片背景不能沿用纯色对比度结果。

## 4. 字体、图标与文案

### 4.1 字体层级

| 样式 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 展览标题 | 28 / 38px | 500–600 | 故事年份、少量章节标题 |
| 页面标题 | 22 / 30px | 600 | 一级页顶部 |
| 内容标题 | 20 / 28px | 600 | 照片或故事详情标题 |
| 小节标题 | 18 / 26px | 600 | 文件、笔记分区 |
| 正文 | 16 / 26px | 400 | 配文、任务说明、输入文本 |
| 操作文字 | 16 / 22px | 500–600 | 按钮、表单标签 |
| 辅助文字 | 14 / 20px | 400 | 日期、目录、状态说明 |
| 导航标签 | 12 / 16px | 500–600 | 底部导航固定短标签 |

正文优先系统字体：PingFang SC、Microsoft YaHei、系统 sans-serif。宋体仅用于主题短句、年份和故事标题，可选本地提供的 Noto Serif SC 子集；没有字体资源时回退系统宋体，不阻塞阅读。中文不使用夸张字间距。英文只作为用户内容或必要专名，不替代中文操作标签。

### 4.2 图标

全站选择一套线性图标，视觉尺寸 22–24px、线宽约 1.75–2px。点击容器至少 44px。一级导航的四个含义分别为日常、相册、心愿、我们；图标下始终有文字。

不用 emoji 充当主要功能图标，不混合多套粗细差异明显的图标。图标资源本地提供并保留来源许可记录。装饰图标对辅助技术隐藏；纯图标按钮有可读名称。

### 4.3 文案语气

内容区可以温柔，操作区必须准确。例：

| 场景 | 推荐文案 |
| --- | --- |
| 新来信 | 有一封给你的信 · 打开 |
| 相册空状态 | 这里还没有照片。记录我们的第一张吧。 |
| 任务提交成功 | 已提交，等待对方确认 |
| 部分上传失败 | 5 张已上传，2 张未成功。重试失败项 |
| 兑换结果未知 | 正在确认兑换结果，请先查看订单 |
| 私密会话失效 | 私密空间已锁定，请重新验证 |
| 删除确认 | 删除这张照片？删除后将无法在相册中找回。 |

不把失败描述为成功，不用诗意文案替代错误原因。只有服务端支持恢复时才展示“撤销”。

## 5. 尺寸、布局与安全区

### 5.1 设计画板

- 主画板：390 × 844 CSS px。此尺寸用于参考，不能在实现中固定页面高度。
- 紧凑验证：360 × 800；宽手机：430 × 932。
- 横屏验证：844 × 390，面板与表单仍可滚动。
- 平板与桌面：768px、1440px 宽；不将手机画板直接等比拉伸。

### 5.2 布局变量

| 项目 | 规范 |
| --- | --- |
| 页面水平边距 | 20px；360px 宽缩至 16px |
| 基础间距 | 4、8、12、16、20、24、32、48px |
| 内容条目间距 | 32px，章节之间 48px |
| 双列图片间距 | 8px |
| 顶栏内容高度 | 56px，安全区另计 |
| 底部导航内容高度 | 56px，底部安全区另计 |
| 主按钮高度 | 至少 48px，长文允许增高 |
| 控件点击区域 | 至少 44 × 44px |
| 图片圆角 | 4px；全屏图片无圆角 |
| 输入与按钮圆角 | 8px |

390px 画板边距为 20px，内容宽 350px，双列单图宽 171px；360px 画板边距为 16px，内容宽 328px，双列单图宽 160px。

顶栏与底栏采用实色底。正文底部预留导航高度及安全区，避免内容被遮挡。浏览器地址栏收起、展开时布局保持可用。实际安全区来自运行环境，不写死刘海高度；设计稿中的系统状态栏仅用于模拟，不作为网页内容绘制。

### 5.3 内容密度

首页不要求把所有重要内容塞入首屏。首屏可以是一张照片与一句配文，向下自然延续。功能页则缩短装饰头部，让用户尽早看到可操作内容。

大字号或系统文字放大时允许换行，按钮与列表高度随内容增长。不能用禁用缩放解决排版问题。

## 6. 信息架构与页面层级

```text
公开入口
  登录 → 必要时设备等待 → 日常

底部四个入口
  日常
    照片 / 故事详情
    来信阅读
    ＋记录 → 发照片 / 记故事 / 写悄悄话
  相册
    文件夹 → 子文件夹 → 照片查看
    上传 / 移动 / 文件夹管理
  心愿
    任务与签到 → 签到、任务、任务确认
    小铺 → 商品、兑换、订单、背包、物品确认、评价
  我们
    双方资料与纪念信息
    故事时间线
    私密空间 → 解锁 → 笔记 / 文件 / 已归档来信
    安全与设备
    账户与退出
```

“心愿”采用两个清楚的入口行“任务与签到”“小铺与礼物”，各有一句说明，不展示数字看板。每个一级页都有顶栏标题和底栏；深层页面用“返回 + 页面名称 + 必要操作”，隐藏底栏。直接访问详情链接时，返回按钮有对应列表作为后备目的地。

从一级入口切换时记住各自位置。返回浏览器历史、关闭大图和切换底栏不能意外提交数据。照片滑动与浏览器边缘返回手势不争抢；始终提供可点击返回按钮。

现有 HTML 地址和受保护入口在实施时保持可访问或提供兼容映射。本文描述视觉页面层级，不要求为每个界面新增一个物理 HTML 文件，也不预先指定框架。

## 7. 页面设计

### 7.1 日常：流动影集

顶部左侧显示站点名称或“我们的日常”，右侧“＋”为记录入口。首次进入展示最近一个有效照片片段，下面是配文和日期；恋爱天数用一行普通辅助文字呈现，不使用超大数字。

内容顺序以时间倒序为主；相同时间使用稳定标识保持排序。首轮不引入算法推荐、无限滚动或智能组图。已有明确分组的数据可以成组展示；缺少分组信息时逐项显示，不猜测事件关联。

照片和手动故事可共同呈现，但同一照片若已被故事引用，不重复作为相邻条目展示。系统签到、购买、积分事件不进入首页生活流，完整故事页仍保留已有合法事件。数据适配只做展示过滤，不删除原始记录。

有未读悄悄话时，在第一段内容之后出现“有一封给你的信 · 打开”，不在首页显示正文预览、发送者私密信息或数字角标。点击实际阅读后才执行既有已读操作。无来信时不占空位。

每日文案作为独立的轻文字片段，标明“今日一句”，不伪装为对方发言，也不和来信共用卡片。纪念日只在既有提醒条件满足时展示一行提示，跳转“我们”；不新增倒计时面板。

照片以完整内容优先，保留原始比例；极长图片可展示有限高度的预览并明确“查看完整照片”。混合比例照片不为追求齐整裁掉人物。首轮不新增封面选择和封面编辑能力。

首页线框：

```text
我们的日常                              ＋

┌────────────────────────────────────┐
│                                    │
│           真实生活照片              │
│                                    │
└────────────────────────────────────┘
那天没有计划，只是一起走了很远。
09.28                         在一起第 N 天

                 有一封给你的信  ↗

九月的几个瞬间
┌────────────────┐ ┌────────────────┐
│      照片       │ │      照片       │
└────────────────┘ └────────────────┘
日期与配文

日常          相册          心愿          我们
```

线框中的日期、配文和章节名是设计占位内容，不写入真实业务。无照片时展示简洁欢迎文字与“记录第一张照片”，不生成虚假生活素材。只有故事时直接展示故事；局部请求失败不隐藏其他已加载内容。

### 7.2 相册

顶部标题“相册”，右侧上传。下方依次为目录路径、文件夹行、标签筛选、双列照片。文件夹采用简洁行或紧凑列表，不伪装成有照片封面的相册；没有真实封面时使用中性图标。

列表缩略图统一 4:5 展示，允许仅展示性裁切；点击后查看完整原图。不得据此修改实际上传文件。图下日期与标题最多两行，完整内容在详情可读。需要管理时进入明确的选择模式，勾选标记具有至少 44px 点击区域；首轮单项操作必须完整，多选操作仅在已有接口能力确认后扩展。

路径过长时保留当前目录和上一级，点击路径打开完整层级面板，避免整行横向溢出。移动和上传均显示完整目标路径，不能仅显示最后一层同名目录。

### 7.3 图片查看器

深炭色背景，图片完整居中，尊重图片方向。顶部返回与更多，底部提供标题、日期和位置。支持左右切换，并提供可点击前后项控件；当前为第几张可用小字显示。

轻点图片可隐藏工具栏，但返回入口应能通过再次轻点恢复。放大查看为增强能力，不以缩放手势作为唯一读取方式。关闭后恢复原目录、筛选和滚动位置。删除当前图片后选中相邻项，最后一张删除后返回列表。

### 7.4 上传与记录

首页“＋”打开三个操作的底部面板：发照片、记故事、写悄悄话。选择后进入全屏表单。

上传顺序：目标目录 → 文件选择与预览 → 现有接口支持的标题/标签 → 提交。上传前显示服务端约束下的格式、单文件大小和数量，不在设计稿写死不存在的限制。相册内打开时默认当前目录；首页打开时默认根目录并明确展示。

逐文件显示等待、上传中、成功、失败。显示真实字节进度；没有进度数据时显示不定进度，禁止伪造百分比。成功项不会因其他失败被清空；重试仅针对失败项。目录已不存在时提示重新选择，不悄悄改为根目录继续提交。

离开未提交表单时提示是否放弃。正在上传时关闭界面与取消传输分开处理，不声称已成功的远端文件被撤回。首轮不承诺浏览器后台上传，用户离开后应能回到相册核对结果。

### 7.5 心愿与任务

“心愿”页使用文字和少量图形组织两个入口，避免奖励总览或待办统计卡。进入“任务与签到”后，顶部显示签到操作与签到结果，下方为待完成、待确认、已确认三个状态分组。

任务为单列，展示标题、说明、执行人、确认人、积分奖励。长说明可展开，主要动作不被截断。状态与按钮必须对应：

| 当前状态 | 当前身份 | 展示 |
| --- | --- | --- |
| 待完成 | 可执行者 | 标记完成 |
| 待确认 | 完成者 | 等待对方确认，无自我确认按钮 |
| 待确认 | 合法确认者 | 确认完成，展示对应奖励 |
| 已确认 | 有查看权限者 | 完成时间与结果，不重复发奖励 |

如任务有双方分别完成等现有细分状态，视觉呈现服从真实状态机，不压缩成错误的单人流程。签到、确认和余额只在服务端确认成功后更新；重复响应展示同一结果。

### 7.6 小铺、背包与订单

小铺页内使用“兑换 / 背包 / 订单”切换。余额在此页清晰可见，但不出现在首页和全局顶栏。商品双列，名称、积分和有效状态在图片下方；无图片时使用统一文字排版。

商品详情是全屏页，底部固定“价格 + 兑换”。确认面板展示商品、数量、总积分、当前余额及预计兑换后余额。购买成功提供查看订单或背包入口。库存、余额改变时保留上下文，展示服务端最新结果。

网络超时不等同购买失败；先查订单结果，同一次重试沿用原请求标识，不新建重复购买。背包区分可用、待确认、已使用，明确操作方。订单评价入口只在服务端允许时显示。

### 7.7 我们与故事

“我们”页顶部为双方头像与称呼，恋爱开始日期和天数用正文层级展示；纪念日与生日采用日期列表。下方是故事、私密空间、安全与设备、账户设置入口。只有支持修改的头像提供编辑动作，不新增资料管理能力。

故事页按年、月组织单列时间线；照片与文字交替，使用细线和日期建立关联。系统事件、照片事件、手动事件用文字区分。新增手动故事包含标题、日期、正文；不默认增加当前接口不支持的图片附件编辑。

只有手动事件显示删除按钮。故事缺失图片时保留文本；单条异常不能使整页空白。日期按站点时区计算和呈现，不由设备时区改变纪念日。

### 7.8 来信与私密空间

来信阅读为全屏正文，发送时间与来源清楚可见；不增加聊天在线状态、输入中、语音通话等新功能。已读仅由接收者触发，遵守已有归档流程，不把私密归档搬到公开生活流。

私密空间进入前显示密码验证页，验证通过后才取回和展示笔记与文件。内部将个人笔记、已归档来信的来源标识清楚，不把所有内容都笼统叫“悄悄话”。只有数据中有可靠来源标识时才分组，不能凭正文猜测来源。

顶部保留“锁定”。退出私密空间不退出网站；主会话结束时一并隐藏私密内容。验证失效后清空显示并返回验证层，敏感正文不写入 URL、浏览器历史状态或持久本地缓存。

上传、下载和删除保留现有鉴权边界。私密输入失败时可在当前已验证会话内保留草稿；会话失效时隐藏草稿且不持久化，提示可能丢失未保存内容，不承诺跨登录恢复。

### 7.9 登录与安全设备

登录采用无真实生活照片的暖白页面，标题、表单和主按钮构成主体。名称与密码字段按实际配置和协议呈现，不能依据旧设计强制新增密码或删除已有验证。

授权等待页突出核对码、有效期和下一步说明。状态分别为等待、批准、拒绝、过期、网络查询失败；网络错误不冒充被拒绝。只有成功领取有效会话后进入业务页。

安全与设备只向有权限者展示管理动作。普通退出保留设备授权；撤销当前浏览器前明确说明即将退出。重新申请创建新待审批记录，不能恢复旧已撤销凭证。不得通过前端“刷新状态”绕过人工审批。

## 8. 共享组件规范

| 组件 | 视觉与状态 | 交互约束 |
| --- | --- | --- |
| 顶栏 | 实色暖白、标题、最多两个主要操作 | 返回按钮可读，长标题省略但详情可读 |
| 底部导航 | 四等分，图标与短标签，选中酒红 | 不显示任务数量、积分或多类角标 |
| 主按钮 | 酒红实底、白字、8px 圆角 | 默认/按下/忙碌/禁用，忙碌时尺寸稳定 |
| 次按钮 | 中性浅底或明确边框 | 不和主操作争夺注意力 |
| 文本链接 | 酒红或深色，具有可辨识样式 | 最小点击区域不因文字短而缩小 |
| 输入框 | 实色底、清晰边界、外置标签 | 聚焦描边，错误信息紧随字段 |
| 分段切换 | 浅底与深色当前项 | 标签短且不截断关键意义 |
| 底部面板 | 顶部圆角、标题、关闭、操作列表 | 可滚动，拖动关闭仅为增强能力 |
| 确认框 | 明确对象与后果、取消、确认 | 危险操作不用默认焦点诱导确认 |
| 轻提示 | 简短文字，位于底栏上方 | 不用于唯一呈现关键错误 |
| 内联错误 | 图标、说明、重试 | 保留原内容或表单上下文 |
| 骨架 | 近似真实图片比例和文本高度 | 减少布局跳动，无强闪烁 |
| 空状态 | 一句解释和最多一个主要操作 | 不用大型插画挤占操作空间 |
| 上传项 | 缩略图、文件名、进度与结果 | 成功失败分别记录，失败可单独重试 |

所有操作状态通过同一套组件呈现，不每页复制一套独立风格。

## 9. 动效、手势与返回行为

- 按钮按下反馈：约 100–150ms，轻微色彩变化；不持续缩放正文。
- 页面进入：约 180–220ms 的轻淡入或短位移；浏览器历史回退优先保持连续性。
- 底部面板：约 220–260ms；背景只加遮罩，不强制大面积模糊。
- 图片切换：约 180–240ms，原图加载不阻塞关闭。
- 减少动态效果开启时移除位移、缩放和闪烁，保留即时状态变化。
- 不要求实现自定义下拉刷新；先提供标准刷新或可见重试入口，避免与浏览器手势冲突。
- 表单编辑状态下关闭或返回须处理未保存内容；不能拦截所有浏览器返回导致用户无法退出。

## 10. 网络、权限与状态设计

| 情况 | 用户看到的结果 | 保留与恢复 |
| --- | --- | --- |
| 首次加载 | 结构稳定的骨架 | 独立模块并行加载 |
| 无数据 | 简短说明与创建入口 | 不填充虚假记录 |
| 图片失败 | 同尺寸占位与重试 | 配文、日期仍保留 |
| 网络中断 | 相关区域提示，允许重试 | 普通表单保留当前内存输入 |
| 提交中 | 按钮忙碌、阻止重复提交 | 不提前宣布成功 |
| 会话失效 | 登录入口与返回提示 | 只保存站内安全返回地址，不保存敏感内容 |
| CSRF 失效 | 安全刷新后按允许规则重试 | 不对所有 403 或写请求盲目重放 |
| 权限不足 | 说明当前操作不可用 | 保留其他有权限的内容 |
| 状态冲突 | 展示最新业务状态 | 刷新受影响区域 |
| 提交结果未知 | 提示核对结果 | 购买、签到、确认遵守幂等边界 |
| 私密认证失效 | 隐藏正文，重新验证 | 不复用普通缓存恢复私密画面 |

401、403、409 等协议处理依赖实际响应，不仅依据 HTTP 数字判断私密认证、设备授权与主会话的区别。UI 不能承担服务端权限校验。

## 11. 可访问性与性能

- 页面、表单、按钮具备语义和标签；键盘可完成导航、打开关闭面板与提交。
- 面板打开时焦点进入，关闭后回到触发控件，背景不能被误操作。
- 焦点描边使用清楚的强调色，不能只依赖阴影。
- 图片有合适替代文本；无法可靠描述时使用已知标题或中性说明，不编造人物行为。
- 正文放大至 200% 时关键功能仍可访问；底栏标签不能与图标重叠。
- 首屏只请求必要缩略图，非首屏按需加载，原图在查看时获取。
- 媒体预留比例，避免图片到达时推动正文跳动。
- 样式、图标、必要字体由本站提供，不把外部 CDN 作为界面可用的前提。
- 不将受保护照片、私密正文放入公共缓存或默认离线缓存；延续服务端访问与缓存规则。
- 性能用实际手机和网络条件验收；本设计不声称已达到任何加载时间指标。

## 12. 平板与桌面适配

手机为主设计。平板扩大边距并增加相册列数，日常阅读宽度保持约 600–680px；桌面可将导航移至顶部或窄侧栏，照片详情拥有更大的查看区域。

1440px 下主容器最大约 1120px，但生活流仍限制阅读宽度；相册可为 4 列。桌面增加可见操作和快捷键提示，不增加手机没有的必要功能。移动端的全屏表单在桌面可呈现为宽度受限的独立内容区。

### 13.4 必须连通的原型路径

- 日常 → 照片 → 返回原浏览位置。
- 相册第三层目录 → 上传 → 部分失败 → 重试失败项 → 同目录结果。
- 日常 → 写悄悄话 → 发送 → 接收方阅读 → 已归档来源标识。
- 心愿 → 完成任务 → 对方确认 → 已确认结果。
- 小铺 → 兑换 → 成功进入订单；另有超时核对结果分支。
- 我们 → 私密验证 → 文件/笔记 → 锁定 → 不再显示内容。
- 登录 → 设备等待 → 批准后进入；另有拒绝、过期、查询失败分支。

原型使用虚拟姓名、日期和中性图片；真实内容只在明确授权的环境中使用。模拟数据必须标明，不作为实际余额、授权或业务结果。

> 设计一款服务固定两人的情侣生活移动 Web 应用，具有原生 App 的导航体验。采用现代画廊风：暖白 #F7F5F1、炭黑 #252422、酒红 #883E4A；正文清楚、照片突出、小圆角、克制留白。主画板 390px，底部为日常、相册、心愿、我们。首页是照片与故事生活流，禁止 KPI、任务统计卡、积分看板、手账胶带、撕纸、玻璃光晕和大面积渐变。操作遵循全屏详情、底部选择面板、返回保留位置。先制作日常、相册、上传三页，并提供空、失败、提交中的组件状态。不得编造真实关系记录。完整规则以本设计文档为准。

## 14. 后续实施边界与依赖

建议先提取视觉变量、导航、状态反馈、输入与弹层，再替换具体页面。业务请求通过现有客户端或兼容适配层承接，视觉组件不自行判断账号权限。

首页照片与故事聚合、返回位置保存、“心愿”入口页、全屏记录流程属于新增前端组织工作，需要实施计划单独拆解。若现有字段无法支持某种分组、来源或分页，优先采用可由真实数据支撑的简化呈现，不静默扩展业务。

UI 重构不改变任务奖励、签到规则、订单状态、照片所有权、私密归属或设备授权规则。后端变更、PWA、原生包、消息推送与离线功能须另列范围。

## 15. 验收标准

### 15.1 风格

- 首页主体为照片/故事，不出现统计卡阵列、积分余额或任务进度面板。
- 不残留手账装饰、英文功能大标题、持续漂浮和整页强制动画。
- 主题色、字号、圆角、图标、按钮和反馈跨页一致。
- 空内容、长标题、无图商品依然成立，不依赖精挑照片才能好看。

### 15.2 手机体验

- 360、390、430px、横屏及 200% 文字放大可用，无关键内容横向溢出。
- 底栏和提交按钮不遮内容、不被安全区或键盘挡住。
- 功能不依赖悬停、长按或隐含手势。
- 四个入口稳定，详情返回恢复目录、筛选和位置。
- 任务、兑换和管理动作在有权限时清晰可达。

### 15.3 业务与异常

- 深层目录上传默认值正确，目录失效有明确处理。
- 部分上传失败不丢成功项；重复点击不产生重复提交。
- 任务完成与确认身份正确，积分和订单以服务端结果为准。
- 来信、每日文案、个人笔记来源不混淆，归档权限不改变。
- 会话失效、授权失效、CSRF、网络失败有各自正确反馈。
- 私密内容在锁定后不可见，登录页不泄漏真实照片或配置。

### 15.4 交付层次

设计文档完成、静态稿完成、原型可点击、代码实现、浏览器验证、线上发布是不同里程碑。当前仅完成设计文档；后续须分别提供对应证据，不能用原型代替实际业务验收。

评审顺序：确认本文视觉与页面组织 → 审阅手机样板与异常状态 → 审阅实施计划 → 实施与验证。本次到文档交付为止。
