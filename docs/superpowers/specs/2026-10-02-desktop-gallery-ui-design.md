# 桌面端生活画廊：UI 与交互设计规范

日期：2026-10-02  
版本：1.0  
状态：设计初稿，待评审。  
交付范围：桌面布局、页面、组件、交互、响应式规则与静态画板；不包含产品代码、接口改动或上线。

## 1. 设计依据与目标

主依据为 [移动端设计规范](2026-10-01-mobile-gallery-ui-design.md)，特别是第 2–6 节视觉与信息架构、第 7 节业务流程及第 12 节桌面适配。桌面端是同一款固定两人使用的生活应用，继续采用「我们之间 · 生活画廊」的表达。

用户本次要求：参照移动端设计，设计桌面端 UI。本稿据此沿用现代画廊风、四个主入口和既有业务能力，以适合鼠标、键盘和宽屏的方式组织内容。站点名称、真实人物称呼由现有配置决定，设计工作名不强制覆盖产品名称。

阅读了当前 `h5/index.html`、`h5/css/gallery-h5.css`、`h5/js/app.js` 及相册服务。当前 H5 的桌面容器最大宽度为 460px，并有深色外衬；本稿提出独立桌面布局，不能把手机容器放大当作完成。工作区已有未提交的产品变更，本次只新增文档与设计文件。

设计成功的判断：

- 桌面打开后首先看到照片与生活内容，功能入口明确。
- 日常和信件保持易读宽度；相册、上传充分使用宽屏。
- 四项导航与移动端一致，没有桌面专属的必要业务步骤。
- 现有任务确认、购买、照片权限、私密验证与设备授权规则保持完整。
- 暖白、炭黑、酒红、小圆角、展签式配文贯穿所有页面。

### 1.1 布局方案比较

| 方案 | 优点 | 代价 | 决策 |
| --- | --- | --- | --- |
| 顶部四项导航 + 页面独立版心 | 四个入口一眼可见，照片空间完整，易与手机对应 | 深层功能需要页内导航 | 本稿采用 |
| 常驻左侧导航 | 适合大量长期可见的功能入口 | 本项目只有四个主入口，容易产生工作台感并挤占照片宽度 | 不采用 |
| 首页多列瀑布生活流 | 同屏展示更多片段 | 文字阅读与时间顺序较难追踪，混合内容焦点分散 | 仅相册使用多列，日常使用单列 |

## 2. 视觉继承与桌面变量

### 2.1 保持一致的视觉语法

背景 `#F7F5F1`，内容面 `#FFFEFC`，主文字 `#252422`，辅助文字 `#68635E`，强调色 `#883E4A`，分隔线 `#DED9D2`，输入边界 `#938B83`。成功、警告、危险、查看器、遮罩色完整沿用移动规范。

酒红用于当前入口、主按钮和必要链接。生活照片自身构成主体色彩；不新增粉紫渐变、玻璃、纸张纹理、胶带、漂浮装饰、自动轮播或大面积投影。首页不显示积分、照片总数、任务统计或进度环。导航不显示数字角标。

图片圆角 4px；按钮、输入、提示 8px；对话框 12px。照片条目采用图像加展签，不套多层卡片。阴影仅辅助弹层层级，常规页面依靠留白和分隔线组织内容。

### 2.2 字体与密度

| 样式 | 字号 / 行高 | 字重 | 使用 |
| --- | --- | --- | --- |
| 站点名称 | 20 / 28px | 500–600 | 全局顶栏 |
| 页面标题 | 32 / 44px | 500–600 | 日常、相册、我们等页首 |
| 章节标题 | 24 / 34px | 500–600 | 年份、故事与内容分区 |
| 内容标题 | 20 / 30px | 600 | 照片标题、商品、任务 |
| 正文 | 16 / 28px | 400 | 配文、说明、信件 |
| 操作 / 导航 | 16 / 24px | 500–600 | 按钮、导航、标签 |
| 辅助文字 | 14 / 22px | 400 | 日期、路径、反馈 |

系统无衬线字体用于正文和操作，优先 Microsoft YaHei、PingFang SC。宋体仅用于站点名、少量页面或故事标题；回退到系统宋体。所有必要字体、样式、图标由本站提供。中文不扩大字距制造装饰感。

间距使用 4、8、12、16、20、24、32、48、64px。桌面内容条目间距 40–48px，章节间距 64px。主按钮至少 44px 高、常规提交按钮 48px 高；所有图标与操作容器至少 44 × 44px，触摸笔记本同样可用。

## 3. 全局布局与响应式

### 3.1 1440px 主画板

主画板为 1440 × 960 CSS px，仅用于静态稿，不固定产品高度。常规页面由文档纵向滚动承载，不在桌面外壳嵌套一个手机滚动窗。

| 变量 | 数值 | 用途 |
| --- | --- | --- |
| `desktop.shell.max` | 1120px | 顶栏与宽页面内容上限 |
| `desktop.shell.gutter` | 32px | 桌面最小左右边距 |
| `desktop.header.height` | 80px | 顶栏，文字放大后可增高 |
| `desktop.page.top` | 48px | 顶栏后至页面标题区域 |
| `desktop.reading.max` | 680px | 日常、信件、故事正文 |
| `desktop.form.max` | 760px | 常规复杂编辑页 |
| `desktop.album.gap` | 24px | 照片列间距 |
| `desktop.viewer.info` | 320px | 大图查看器信息区 |
| `desktop.dialog.max` | 480px | 简短确认与目录选择 |

1440px 宽时，宽版心为 x=160 至 x=1280，日常阅读区为 x=380 至 x=1060。相册四列，每列 `(1120 - 3 × 24) / 4 = 262px`。1920px 宽也不无限拉宽正文或增加为六列，外围留白自然增长。

### 3.2 顶栏

左侧站点名，中央四项「日常 / 相册 / 心愿 / 我们」，右侧「＋记录」。当前项使用酒红文字、较高字重及短下划线；不只依赖颜色。站点名链接至日常。

「＋记录」展开锚定于按钮的菜单：发照片、记故事、写悄悄话；打开即聚焦首项，支持键盘、点击外部和 Escape 关闭。复杂表单进入独立页面。没有全站搜索、余额、通知数量或新工具栏。

顶栏 sticky、暖白实底、细底线；允许缩放后随内容增高。锚点滚动和焦点滚动预留顶栏高度。一级页面呈现完整顶栏；编辑页保留简化站点标识与返回，避免多个导航入口分散提交注意力。深层详情仍有明确「返回 + 名称」，弹层打开时背景顶栏不可操作。

### 3.3 断点与降级

| CSS 可用宽度 | 导航 | 内容与相册 | 查看器 / 表单 |
| --- | --- | --- | --- |
| ≥1200px | 80px 顶部四项导航 | 版心≤1120px，边距≥32px，相册四列、24px 列距 | 查看器图片 + 320px 信息栏；上传双区 |
| 1024–1199px | 72px 顶部导航，压缩间距 | 左右24px，相册三列、20px 列距 | 查看器图片 + 288px 信息栏；上传单列 |
| 768–1023px | 简化顶栏 + 原四项底部导航 | 左右24px，相册三列、16px 列距，阅读区≤680px | 查看器信息移至下方，所有编辑单列 |
| <768px | 移动端原四项底部导航 | 按移动规范，手机双列、8px 列距 | 移动全屏详情、编辑及底部面板 |

例如 1024px 下内容宽 976px，三列约312px；768px 下内容宽720px，三列约229px。断点基于布局可用空间，不按操作系统或 UA 判断。顶部导航与底部导航不能同时出现。

浏览器 200% 放大时自然进入较窄布局，正文不锁死高度，操作允许换行。每种布局使用同一数据和操作规则；切换宽度保留当前目录、筛选、详情对象和未提交内容，不重新发出写请求。

## 4. 页面设计

### 4.1 日常：一条可停留的生活影集

居中680px。标题「我们的日常」及一行真实关系日期 / 天数，下方最近有效照片、图外配文与日期。关系数字保持普通正文层级。首屏不是功能总览，也不设常驻右侧统计栏。

照片按真实比例显示；很长的图只限制预览高度并提供「查看完整照片」。支持已有明确关联的双图片段，每列328px、24px 间隔；不凭接近的上传时间猜测同一事件。纵向默认按时间倒序，并使用稳定标识处理相同时间。

实际存在新来信时，在第一段内容之后呈现细线分隔的「有一封给你的信 · 打开」，不展示正文。今日一句独立标明来源。纪念日仅满足原提醒条件时出现普通文字入口；不创建倒计时看板。

无照片时让真实故事承担主体；没有任何内容时以简洁文字和记录入口结束，不填充 AI 关系照片。图加载失败保留配文、日期和原比例占位。某个模块失败不阻塞整个日常页。

```text
我们之间          日常  相册  心愿  我们                ＋记录
──────────────────────────────────────────────────────────
                   我们的日常
                   普通层级的关系日期
                   ┌────────────────────┐
                   │     完整生活照片    │
                   └────────────────────┘
                   配文                         日期
                   ─ 有一封给你的信 · 打开 ─
                   后续照片 / 故事 / 今日一句
```

### 4.2 相册：宽版心、目录行、四列照片

1120px宽版心。标题左置；右侧「管理」「上传照片」。标题下为完整面包屑，下一行为当前目录下的文件夹；没有封面时用中性文件夹图标和名称。标签筛选位于照片区上方，仅使用实际已有标签。

目录默认横向紧凑列表，过多时自然换行或显式「更多文件夹」；首轮不常驻目录树。路径过长时保留根目录、上一级、当前级，中间通过「…」打开完整路径；上传 / 移动对话框必须显示完整目标路径。

照片按原有列表顺序排列为四列，缩略图4:5，仅展示性裁切，完整图在查看器。每张下方是两行以内标题及日期，不使用悬停覆盖正文。列表点击目标与「更多」操作明确分离；后者在键盘聚焦和触摸时同样可达。

「管理」进入明确选择态：标题旁提供退出，选择框至少44px。不因为桌面空间充足就承诺批量删除、批量移动、拖放移动或桌面专属排序；这些能力须核实接口后另行扩展。单张移动、删除和文件夹新建 / 重命名 / 删除遵守既有权限与后果说明。

返回时恢复目录、标签、数据顺序与滚动位置。相册和日常的大图来源独立，不能用相册筛选后的数组决定日常照片顺序。

### 4.3 大图查看：完整照片与独立展签

大图以覆盖全窗口的深炭色查看层展示，不依赖浏览器 Fullscreen API。顶部是44px「关闭」和当前位置文字；照片区与右侧320px信息栏分离。右栏暖白实底，包含标题、日期、完整目录、已有标签及合法的单张操作。

图片区扣除信息栏、64px 顶部和两侧安全内边距，图片按 contain 居中，尊重方向，不裁切原图。左右切换按钮有实色底，常驻且可聚焦；缩略图不强制额外下载。原图加载失败不影响关闭和信息阅读。

左右方向键切换，Escape关闭；仅查看层激活、焦点不在文本编辑控件时处理快捷键。不要注册全站单字母、Delete删除或劫持浏览器缩放。缩放仅作为增强能力，若实施须提供可见「放大 / 缩小 / 适应窗口」控件，不只依赖滚轮。

信息栏允许自身滚动，避免长路径和标题把动作推出可达范围。窗口<1024px时转为图下信息区，与手机详情一致。首末项禁用对应切换，删除当前项后落到相邻项，最后一张删除后回列表。

关闭后恢复原触发项焦点与原列表位置。私密照片也只在已验证的私密范围加载，不与普通相册来源混用。

### 4.4 上传：文件队列与明确目的地

一级记录菜单的发照片和相册上传进入同一独立编辑页。简化顶栏下「返回相册 / 上传照片」，明确返回位置。≥1200px时使用1120px版心：左704px文件选择与队列，右384px目标目录与说明，间隔32px；较窄时单列≤760px。

左侧选择区提供「选择照片」，允许拖文件到标明的区域作为增强方式。拖拽不得替代按钮，也不扩展为文件夹上传、后台驻留上传或自动提交。文件限制使用服务端真实能力，未确认时不写死数量与MB上限。

右侧按「目标目录 → 已有标题 / 标签字段 → 操作」组织。相册入口默认当前目录，日常入口默认根目录；两者都呈现完整路径。字段是否按单张编辑以实际接口为准，本稿不新增批量配文能力。目标不存在时阻止提交并要求重新选择，不能自动转至根目录。

上传队列每项包含预览、文件名、实际大小、状态与动作。四态为待上传、上传中、已上传、失败。只有真实进度事件才显示字节与百分比；静态稿示例进度明确为模拟值。成功项保留，失败项可单独重试。文件名过长可折行，不压缩成无法辨别的省略文本。

上传期间禁止重发该项，已确认结果来自服务端。操作区根据状态显示「开始上传」「重试失败项」「返回相册核对」，不得用「全部完成」掩盖部分失败。选择文件后的未提交返回需确认放弃。进行中的关闭与取消传输分别说明，取消不撤回已成功的文件。

操作区不使用遮挡列表的悬浮底条，短屏通过文档滚动可达；长队列可提供锚点跳转到结果和提交区。目标目录只在适当的上传阶段允许调整，不能把正在传输的单项悄悄改目标。

### 4.5 心愿、任务与签到

心愿首页≤760px，标题下两行入口「任务与签到」「小铺与礼物」，各一句解释。没有待办汇总、积分总览或奖励数字卡。

任务页≤880px，签到作为第一行操作与结果，下面按待完成、待确认、已确认分组。任务采用文字行，左侧标题与说明，中间角色 / 奖励，右侧合法操作；长说明自然展开，窄屏动作换至下一行。首轮不用横向看板或表格处理长任务说明。

| 状态 / 身份 | 桌面呈现 |
| --- | --- |
| 待完成 / 合法执行者 | 「标记完成」 |
| 待确认 / 完成者 | 「等待对方确认」，没有自我确认按钮 |
| 待确认 / 合法确认者 | 「确认完成」，说明对应奖励 |
| 已确认 | 完成结果与时间，没有重复发奖按钮 |

双方分别完成等细分状态按真实状态机呈现。签到、确认与余额在服务端成功后更新；失败保留该任务上下文。浏览器多窗口状态冲突时展示最新结果，不乐观重复发奖。

### 4.6 小铺、背包与订单

宽版心使用「兑换 / 背包 / 订单」页内切换，余额只在这个业务范围显示。商品四列，照片 / 统一文字封面、名称、积分、有效状态位于图下；不使用悬停才能找到的兑换按钮。

商品详情采用宽版心双区：左完整商品展示，右约360px名称、说明、价格与「兑换」。窄屏单列。确认对话框≤480px，展示商品、数量、总积分、当前及预计余额；使用最新服务端限制。网络超时进入「正在确认兑换结果」和订单核对入口，同次重试沿用请求标识。

背包用状态分组列表，区分可用、待确认、已使用和合法操作方。订单在宽屏可用语义表格，主要列为商品 / 时间 / 积分 / 状态 / 操作；窄屏变为单列摘要，完整订单号在详情可复制。评价入口严格依据服务端允许状态，不增加新评价规则。

### 4.7 我们与故事

「我们」主版心880px。双方头像与称呼置于顶部；开始日期和恋爱天数为普通文字。下方左侧约520px重要日期列表，右侧约312px四行入口：故事、私密空间、安全与设备、账户设置，间隔48px。进入窄屏则依次堆叠。没有照片数量、签到天数等额外统计。

故事正文≤680px，按年、月排列单列时间线，日期列约88px，正文与真实图片交替。长正文可展开；缺失图片保留文字。系统、照片、手动事件明确来源；只有手动事件提供既有删除动作。新增手动故事仅包含当前支持的标题、日期和正文。

纪念日期以站点时区呈现，设备时区不改变业务日期；日、月、年与生日提醒服从已有计算规则。

### 4.8 写信、阅读与私密空间

写信与阅读均为独立≤680px正文区。阅读显示来源和时间；接收者实际阅读才执行既有已读动作。没有聊天在线状态、输入中或公共来信预览。写信显示完整表单标签、发送与返回，服务端失败保留当前已授权会话内输入，不假装发送完成。

私密空间首先显示≤400px验证区，只有验证通过后才请求敏感内容。输入方式依据实际配置，不固定四位PIN，也不强制只使用鼠标软键盘。进入后顶部明确「私密空间」「锁定」；宽版心左240px笔记 / 文件来源与列表，右正文；窄屏列表与详情分层。

个人笔记、归档来信必须有可靠来源才分组。敏感正文不进入URL、history.state或持久浏览器缓存；锁定后正文、列表预览及敏感草稿都隐藏。失效与主会话退出同样清空展示和内存引用，不能后退恢复私密画面。后台标签页与浏览器返回行为须单独验证，UI隐藏不能替代服务端鉴权。

### 4.9 登录、安全与设备

登录全窗口暖白，表单≤400px，垂直留白随视口调整，短屏从顶部自然滚动。没有任何真实情侣照片、敏感名字预填或旧手账装饰。字段由真实登录协议决定；名称、密码与设备核对流程不因UI重做而改变。

设备授权等待页≤480px，突出核对码、有效期和操作说明。等待、批准、拒绝、过期、查询失败五种状态各有文案；只有领取有效会话成功后进入业务页面。

安全与设备页≤880px，设备列表一行一个，可读名称、最近活动、授权状态与合法管理动作。撤销当前浏览器明确提示即将退出；普通退出保留设备授权，重新申请创建新待审记录。桌面窗口不能借「刷新状态」绕过审批。

## 5. 共享组件与交互

| 移动组件 | 桌面表达 | 必须保留 |
| --- | --- | --- |
| 四项底栏 | 顶部四项导航 | 相同入口、当前项、位置恢复 |
| 记录底部面板 | 锚定记录按钮的菜单 | 三个操作、关闭、键盘与焦点 |
| 全屏编辑 | 简化顶栏下的独立受限版心 | 外置标签、草稿返回处理 |
| 全屏大图 | 深色查看层 + 信息栏 | 完整原图、关闭、前后项 |
| 目录选择面板 | ≤480px对话框 | 完整路径、同名目录可区分 |
| 删除确认 | ≤480px居中对话框 | 对象、后果、取消、确认 |
| 轻提示 | 视口底部居中的简短提示 | 关键错误另有内联说明 |
| 移动列表 | 展签、行布局或适合的表格 | 权限、真实状态、不隐藏正文 |

弹层打开后焦点进入，Tab循环在活动弹层；关闭后还原到触发控件，触发项被删时落到相邻项或列表标题。背景不可操作。危险确认默认聚焦取消；Escape关闭普通弹层，但正在提交的结果与草稿处理要有明确分支，不能静默放弃。

悬停仅用于轻微背景变化和辅助提示，不增加必需步骤。右键菜单、拖放、双击不是唯一动作；单击和键盘均可完成主流程。所有页内选择项使用真实button / link / input语义，图标按钮有可读名称。

动效继承移动规范：按下约100–150ms，内容进入约180–220ms，查看器约180–240ms；不强制每次导航整页动画。减少动态效果时移除位移与缩放。锚定菜单不会越过视口，空间不足改为上方展开或窄屏底部面板。

## 6. 业务、网络与安全状态

| 情况 | 反馈位置与恢复 |
| --- | --- |
| 首次加载 | 在真实版式位置显示骨架，不让网格列数跳变 |
| 空目录 / 无内容 | 页面说明与一个主要创建入口，不用示意数据填充生产 |
| 照片失败 | 同比例占位、图外标题和日期保留、重试 |
| 局部加载失败 | 失败区域内联提示，其余模块继续可用 |
| 提交中 | 当前按钮忙碌、尺寸稳定，禁用同次重复提交 |
| 部分上传失败 | 分项结果保留，只重试失败项 |
| 结果未知 | 先核对订单 / 签到 / 确认状态，不生成第二个业务请求 |
| 目录失效 / 业务冲突 | 保留输入，明确重新选择或刷新受影响区域 |
| 会话 / CSRF / 权限异常 | 按实际响应区分处理，只在已有安全规则允许时重试 |
| 私密验证失效 | 隐藏敏感内容与草稿，重新验证，不复用缓存 |

UI不承担服务端权限校验。没有可靠批量、分页、来源标识等接口时，使用真实能力支撑的简化呈现。不能把HTTP 403一律当成CSRF失败，也不能对所有写请求自动重放。

## 8. 实施边界与验收

后续实施先建立共享颜色、字体、尺寸和组件，再将同一业务数据接入不同布局。保留现有HTML入口或兼容映射，不因桌面设计强制换框架、拆路由或重写后端。当前H5源码与移动文档已有差异，例如自动轮播、封面选择和私密输入表达；本稿仍以用户指定的移动设计规范为视觉依据，实施时须逐项核对实际能力与最新决定，不默认复制所有H5差异。

### 8.1 视觉与版式

- 1440×960下顶栏、相册与宽页面共用1120px版心，日常正文≤680px。
- 相册1440px四列、1024px三列；查看器窄于1024px信息移至下方。
- 1920px下文字不无限拉长；1280×720下表单与查看器操作完整可达。
- 没有手机深色外衬与460px桌面容器，没有统计卡阵列、手账装饰或自动轮播。
- 长标题、长路径、无图商品、竖图、极长图、失败图都保持可读。

### 8.2 交互与可访问性

- 鼠标、键盘及触摸均可导航、记录、上传、查看和返回。
- 查看器方向键与Escape只作用于激活层，文本输入不被劫持。
- 弹层焦点、关闭还原、背景隔离、危险取消默认焦点正确。
- 200%缩放及宽度切换无关键横向溢出，粘性顶栏不挡焦点。
- 按钮、正文、输入边界和焦点的实际对比度完成检查。
- 减少动态效果、无外部CDN、首屏缩略图按需加载均须实测。

### 8.3 业务与隐私

- 相册 / 日常查看来源独立，关闭恢复原目录、筛选和位置。
- 深目录上传默认正确、完整路径可见、目录失效阻止误投。
- 成功文件不重传，进度来自真实事件，未知结果先核对。
- 任务身份、余额更新、购买幂等、订单状态与服务端一致。
- 私密内容仅验证后获取，锁定、失效、退出与后退均不复现。
- 设备重新授权不恢复旧撤销凭证，普通退出不撤销设备。

本次完成的是设计规范与五张静态稿。交互原型、产品实现、业务测试、响应式浏览器验收和线上发布须分别提供证据。本设计稿评审后才进入实施范围。
