# Couple Website 可售安装版需求文档

## 1. 文档信息

- 文档版本：v0.1
- 创建日期：2026-06-24
- 项目代号：Couple Website Commercial Installable Edition
- 目标形态：可售卖、可交付、可由个人用户部署到自己服务器的单站点安装版
- 当前基础：PHP + HTML/CSS/JavaScript + JSON 文件存储

## 2. 背景与目标

当前项目适合作为情侣私密互动网站使用，但仍偏向个人自用代码包。若要作为商品销售给个人用户，需要从“会改代码的人能跑起来”升级为“普通购买者按说明即可安装、配置、更新、备份和长期使用”。

本阶段目标不是做 SaaS 平台，而是先做单租户可安装商业版：每个购买者部署一份独立网站，数据存放在购买者自己的服务器上。

### 2.1 核心目标

1. 降低安装门槛：购买者不需要手动编辑 PHP 或 JSON 文件即可完成安装。
2. 提升商业交付质量：具备安装向导、管理后台、授权信息、备份恢复、部署文档。
3. 提升安全底线：登录、文件上传、私密空间、数据访问、配置文件、错误输出等达到可售卖产品的基础安全要求。
4. 提升可维护性：从零散 JSON 文件逐步迁移到 SQLite 优先、MySQL 可选的数据层。
5. 保留当前产品气质：情侣纪念、相册、任务、商店、私密空间、悄悄话、故事线仍是核心体验。

### 2.2 非目标

以下内容不纳入第一阶段：

1. 多租户 SaaS 平台。
2. App Store / Google Play 原生 App 上架。
3. 商家后台、分销系统、平台代理系统。
4. 复杂在线支付结算系统。
5. 企业级组织、团队、权限矩阵。

## 3. 用户与使用场景

### 3.1 购买者

购买者通常是个人用户、情侣、学生、内容创作者或轻技术用户。他们希望购买后能将网站部署到自己的服务器、虚拟主机、宝塔面板、Docker 环境或云服务器中。

### 3.2 站点管理员

站点管理员通常就是购买者本人。管理员负责初始化站点、配置情侣双方账号、修改主题、管理备份、配置 AI 服务、查看运行状态。

### 3.3 站点成员

站点成员通常只有两个人。成员使用登录页进入网站，使用相册、任务、商店、私密空间、悄悄话、故事线等功能。

## 5. 功能需求

## 5.1 安装向导

安装向导是可售安装版的入口。首次访问未安装站点时，系统应自动跳转到安装页面。

### 5.1.1 环境检测

系统应检测以下项目：

1. PHP 版本。
2. 必需扩展：json、mbstring、fileinfo、pdo、pdo_sqlite、gd。
3. 可选扩展：imagick、pdo_mysql、zip、curl、openssl。
4. 目录写入权限：data、uploads、storage、cache、logs。
5. Web 服务器重写规则是否可用。
6. 最大上传大小。
7. session 是否可用。
8. HTTPS 是否启用。

验收标准：

1. 缺少必需项时，安装流程不可继续。
2. 缺少可选项时，页面明确说明会影响哪些功能。
3. 所有检测结果都以普通用户能理解的语言展示。

### 5.1.2 数据存储选择

第一阶段默认使用 SQLite，后续保留 MySQL 选项。

要求：

1. 默认创建 SQLite 数据库文件。
2. 数据库文件不得直接暴露在 Web 可访问目录中。
3. 初始化时自动创建数据表。
4. 支持从旧 JSON 数据导入。
5. 若用户选择 MySQL，需要填写主机、端口、数据库名、用户名、密码。

验收标准：

1. 全新安装无需手动创建数据表。
2. 安装失败时不会留下半初始化状态。
3. 重复刷新安装页面不会重复写入脏数据。

### 5.1.3 站点基础配置

安装时需要填写：

1. 站点名称。
2. 站点公开访问地址。
3. 时区。
4. 恋爱开始日期。
5. 是否启用 AI 功能。
6. 是否启用商城功能。
7. 是否启用私密空间。

验收标准：

1. 配置完成后可在后台继续修改。
2. 配置文件或数据库中不保存明文敏感密钥。
3. 表单具备基础校验和错误提示。

### 5.1.4 账号初始化

安装时创建：

1. 管理员账号。
2. 情侣成员 A。
3. 情侣成员 B。

账号要求：

1. 登录密码必须使用安全哈希保存。
2. 私密空间密码与登录密码分离。
3. 支持安装后修改昵称、头像、生日、纪念日。
4. 不允许空密码。

验收标准：

1. 安装完成后可直接登录后台。
2. 情侣双方可登录前台。
3. 忘记密码流程至少提供“管理员重置成员密码”能力。

## 5.2 后台管理

后台管理用于让购买者无需改代码即可维护站点。

### 5.2.1 后台首页

展示：

1. 当前版本。
2. 安装状态。
3. PHP 版本和关键扩展状态。
4. 数据库状态。
5. 上传目录状态。
6. 最近备份时间。
7. 安全提醒。

验收标准：

1. 管理员登录后可以看到系统健康状态。
2. 严重问题需要显著提示。
3. 普通成员不可访问后台。

### 5.2.2 站点配置

后台可修改：

1. 站点名称。
2. 恋爱开始日期。
3. 主题色。
4. 首页展示模块。
5. 功能开关。
6. AI 服务配置。
7. 上传限制。

验收标准：

1. 修改后立即生效或明确提示需要刷新。
2. 敏感字段编辑时不回显完整密钥。
3. 配置保存失败时不破坏旧配置。

### 5.2.3 用户管理

后台可执行：

1. 修改成员昵称、生日、头像。
2. 重置登录密码。
3. 重置私密空间密码。
4. 查看最近登录时间。
5. 强制退出所有会话。

验收标准：

1. 密码重置后旧密码失效。
2. 管理员无法查看用户明文密码。
3. 操作需要 CSRF 防护。

## 5.3 授权与商业交付

第一阶段采用混合授权：默认支持在线激活并绑定域名或安装实例，同时生成本地签名授权文件；无法联网的客户可使用离线授权文件激活。授权验证不得读取或上传用户照片、私密文件、悄悄话、笔记等业务数据。

### 5.3.1 授权信息

系统记录：

1. 授权码。
2. 授权 ID。
3. 授权类型：个人版、家庭版、商业定制版。
4. 授权域名。
5. 安装实例 ID。
6. 授权邮箱。
7. 免费更新期限：永久。
8. 当前版本。
9. 本地授权文件签名。
10. 最近一次授权校验时间。
11. 核心源码完整性状态。

验收标准：

1. 未填写授权时，后台显示未激活提示。
2. 授权失败不应破坏已有数据。
3. 在线激活成功后，本地生成可离线校验的签名授权文件。
4. 授权服务器不可用时，系统应提供宽限期，避免客户站点立即不可用。
5. 在线授权校验只上传授权 ID、域名、安装实例 ID、版本号和核心文件完整性状态。

### 5.3.2 源码完整性检查

商业版不允许购买者修改核心源码。首发版本通过核心文件哈希比对进行保护，不以混淆或加密作为首要手段。

要求：

1. 每个正式版本生成核心文件清单。
2. 文件清单记录核心 PHP、JS、CSS 文件路径和 SHA-256 哈希。
3. 文件清单由官方私钥签名，避免被伪造。
4. 安装器和后台可在本地检查核心文件是否被修改。
5. 在线激活、在线更新、付费主题下载和售后诊断时，可上报核心文件完整性状态。
6. 只校验核心文件，不校验用户上传文件、用户数据、主题资源、配置文件和日志文件。

验收标准：

1. 核心源码被修改后，后台能显示明确提醒。
2. 核心源码被修改后，可限制在线更新、官方安装服务、主题交付或售后支持。
3. 完整性检查不得上传用户隐私数据。
4. 文档和授权协议需明确：完整性检查用于发现差异和约束服务权益，不保证在客户完全控制服务器时绝对阻止源码修改。

### 5.3.3 交付包要求

交付包应包含：

1. 可运行代码包。
2. 安装说明。
3. 升级说明。
4. 变更日志。
5. 许可证说明。
6. 默认配置示例。
7. 安全部署建议。
8. 核心文件完整性清单。
9. 内置免费主题。

验收标准：

1. 用户解压后能找到清晰的安装入口。
2. 交付包不包含开发机的真实配置、密钥、日志和测试数据。
3. 交付包内不包含不应公开的 Git 历史或临时文件。

## 5.4 数据层改造

当前 JSON 文件适合个人项目，但商业安装版需要更稳定的数据层。

### 5.4.1 SQLite 优先

第一阶段确认将核心数据迁移到 SQLite：

1. users。
2. settings。
3. photos。
4. folders。
5. tasks。
6. checkins。
7. shop_products。
8. orders。
9. reviews。
10. whispers。
11. story_events。
12. private_notes。
13. private_files。
14. audit_logs。

验收标准：

1. 所有新安装默认写入 SQLite。
2. 旧 JSON 文件可被导入。
3. 导入前自动备份原 JSON 数据。
4. 数据访问通过统一 Repository 或 Service 层完成。

### 5.4.2 迁移工具

需要提供迁移工具：

1. 检测现有 JSON 数据。
2. 预览将导入的数据数量。
3. 执行导入。
4. 生成迁移日志。
5. 支持失败回滚或重复安全执行。

验收标准：

1. 重复执行不会产生重复数据。
2. 迁移失败时能定位失败原因。
3. 迁移完成后旧数据不会被立即删除。

## 5.5 备份与恢复

商业安装版必须让用户能保护自己的数据。

### 5.5.1 备份

备份内容包括：

1. 数据库。
2. 上传文件。
3. 配置文件。
4. AI 配置，敏感字段可选择排除或加密。

备份方式：

1. 手动创建备份。
2. 下载备份包。
3. 本地服务器保留最近 N 份备份。

验收标准：

1. 管理员可一键创建备份。
2. 备份包文件名包含日期和版本。
3. 备份包不能被未登录用户下载。

### 5.5.2 恢复

恢复要求：

1. 上传备份包。
2. 校验备份包结构。
3. 恢复前自动创建当前状态备份。
4. 恢复数据库和上传文件。

验收标准：

1. 恢复失败时不破坏当前站点。
2. 恢复完成后提示重新登录。
3. 不允许恢复来源不明的可执行脚本文件。

## 5.6 安全需求

### 5.6.1 登录与会话

要求：

1. 所有账号密码使用 password_hash 保存。
2. 登录接口需要 CSRF 防护。
3. 登录失败需要限流。
4. Session Cookie 启用 HttpOnly、SameSite。
5. HTTPS 下启用 Secure Cookie。
6. 支持管理员强制退出所有会话。

验收标准：

1. 数据库和配置中不出现新写入的明文密码。
2. 连续失败登录会被延迟或暂时锁定。
3. 退出登录后旧会话不可继续访问 API。

### 5.6.2 文件上传

要求：

1. 使用服务端 MIME 检测。
2. 限制扩展名和文件大小。
3. 上传文件重命名。
4. 私密文件必须通过受控下载接口读取。
5. 禁止上传 PHP、HTML、SVG、JS 等高风险文件类型。
6. 上传目录禁止执行脚本。

验收标准：

1. 上传恶意脚本不会被执行。
2. 私密文件不能通过直链访问。
3. 文件删除只能删除当前站点授权范围内文件。

### 5.6.3 API 与数据访问

要求：

1. 所有写操作必须校验登录态和 CSRF。
2. 所有敏感读操作必须校验登录态。
3. 输入统一校验、过滤和长度限制。
4. 输出避免直接渲染用户提交的 HTML。
5. 错误信息不泄露服务器路径、密钥和 SQL。

验收标准：

1. 未登录访问敏感 API 返回 401 或 403。
2. 普通成员不能访问后台 API。
3. 前端展示用户内容时不会执行脚本。

### 5.6.4 日志与审计

记录：

1. 登录成功与失败。
2. 管理员配置变更。
3. 密码重置。
4. 文件上传与删除。
5. 备份与恢复。
6. 授权状态变化。

验收标准：

1. 管理员可查看最近操作日志。
2. 日志不记录明文密码、完整密钥和私密内容。
3. 日志文件不可被公网直接访问。

## 5.7 前台体验保留与优化

前台功能原则上保留当前项目能力。

### 5.7.1 首页

2. 每日文案。
3. 纪念日提醒。
4. 余额或任务摘要。
5. 快捷入口。

新增：

2. 移动端布局优化。

### 5.7.2 相册

保留：

1. 图片上传。
2. 文件夹。
3. 标签。
4. 缩略图。
5. 删除。

新增：

1. 上传前压缩选项。
2. 后台设置最大上传大小。
3. 批量导出相册数据。

### 5.7.3 任务与签到

保留：

1. 每日签到。
2. 任务列表。
3. 奖励余额。
4. 完成记录。

新增：

1. 后台维护任务池。

### 5.7.4 商店

保留：

1. 商品列表。
2. 虚拟商品。

### 5.7.5 私密空间

## 5.8 移动端与 PWA

第一阶段至少完成基础移动端可用性，PWA 可作为第一阶段后半段或第二阶段。

要求：

1. 登录页适配手机。
2. 首页、相册、任务、商店、私密空间在 375px 宽度下可用。
3. 按钮触控区域不小于 44px。
4. 上传照片在手机浏览器中可用。
5. 增加 manifest.json。
6. 增加 App 图标。
7. 提供离线不可用提示。

验收标准：

1. iPhone 和 Android 常见浏览器中主要流程可用。
2. 页面没有横向溢出。
3. 用户可以添加到手机桌面。

## 5.9 主题系统与主题售卖

商业版提供内置免费主题，并支持额外付费主题包。用户可以在后台切换主题、修改字体和基础视觉配置，但不直接修改核心源码。

要求：

1. 提供不少于 2 套内置免费主题。
2. 支持后台修改字体、主题色、圆角、背景纹理或背景图等基础样式。
3. 部分高级主题包需要额外付费授权。
4. 主题系统采用模板覆盖方式，不直接改核心页面源码。
5. 主题包应有独立目录、主题配置文件、预览图和版本信息。
6. 主题包下载和启用需要校验授权状态。
7. 官方主题定制服务可基于模板覆盖机制交付。

验收标准：

1. 管理员可在后台切换内置主题。
2. 字体修改不需要编辑源码。
3. 未授权用户不能启用付费主题包。
4. 主题包更新不应覆盖用户数据。

## 6. 非功能需求

## 6.1 部署兼容性

支持环境：

1. Docker Compose，作为首发推荐部署方式。
2. Nginx + PHP-FPM。
3. Apache + PHP。
4. PHP 内置服务器，仅用于开发。
5. 宝塔面板部署文档，仅作为可选参考。

验收标准：

1. 提供 Docker Compose 部署文件和说明。
2. 明确生产环境不建议使用 PHP 内置服务器。
3. 提供 Apache 和 Nginx 配置示例。
4. 文档说明目录权限设置。
5. 第一版不兼容无命令行环境，安装文档需明确说明需要服务器命令行或面板终端能力。

## 6.2 性能

要求：

1. 首页首屏资源合理压缩。
2. 相册缩略图不加载原图。
3. 常用配置可缓存。
4. 上传图片生成缩略图。
5. 上传商品图片时生成缩略图。
6. API 响应保持稳定。

验收标准：

1. 1000 张照片以内，相册列表仍可正常打开。
2. 500 种商品以内，商品图片可以迅速打开。
3. 首页常规请求不依赖外部 AI 接口阻塞。
4. AI 失败时降级到本地文案。

## 6.3 可维护性

要求：

1. 业务逻辑逐步从散落 API 中抽到 includes/service 层。
2. 数据访问统一封装。
3. 配置读取统一封装。
4. 公共错误响应统一封装。
5. 增加基础自动化检查。

验收标准：

1. 新增功能不直接手写重复数据库连接逻辑。
2. API 错误格式一致。
3. 至少有 PHP 语法检查和核心接口冒烟测试。

## 6.4 合规与声明

需要准备：

1. 软件许可协议。
2. 用户使用协议模板。
3. 隐私政策模板。
4. 第三方依赖与素材授权清单。
5. AI 服务使用说明。
6. 支付方式说明，若接入第三方支付则避免自行保存银行卡信息。

验收标准：

1. 交付包中包含 license 文件。
2. README 明确商业授权方式。
3. 隐私政策说明数据由购买者自托管保存。
4. 法律文本上线前需由专业人士确认。

## 10. 风险与待确认

本节用于记录商业化前必须明确的产品、技术、法务和运营决策。已经确认的内容应转入需求范围；仍未确认的内容应在开发前继续讨论，避免后期反复返工。

### 10.1 已确认产品决策

1. 不允许购买者修改源码。商业版应以可安装交付包形式提供，购买者可以通过后台、安装向导、主题配置、插件或配置文件完成个性化，不直接修改核心源码。
2. 提供安装服务。除自助安装文档外，可提供付费或套餐内安装服务，覆盖服务器环境检查、部署、初始配置、HTTPS 建议和基础功能验收。
3. 提供主题定制服务。商业版应支持多种前端风格，例如手账风、极简风、胶片相册风、赛博像素风、节日主题风等，并允许后续按客户需求定制主题。
4. PHP 版本升级。第一版可售安装版不再以 PHP 7.4 作为目标环境，应将最低要求升级到 PHP 8.2+，推荐生产环境使用 PHP 8.3 或 PHP 8.4，并在部署文档中明确推荐版本和必需扩展。
5. 授权方式采用混合授权。默认支持在线激活并绑定域名或安装实例，同时生成本地签名授权文件；无法联网的客户可使用离线授权文件激活。授权服务器不可用时应提供宽限期，避免客户站点立即不可用。
6. 源码完整性检查作为辅助约束。系统可通过版本清单、文件哈希和服务端校验发现核心源码差异，并据此限制在线更新、安装服务、主题交付或售后支持，但不应宣称可以在客户完全控制服务器时绝对阻止源码修改。
7. 免费更新期限为永久。购买者获得当前授权版本线下的长期更新权益，后续若推出大版本、主题包或增值服务，需另行定义售卖规则，但不影响已购版本的可用性。
8. 源码保护方式采用核心文件哈希比对。首发不以源码混淆或加密作为主要保护方式，优先通过授权协议、核心文件完整性检查、官方更新和售后权益约束修改源码行为。
9. 主题定制售卖方式为内置免费主题 + 付费主题包 + 字体配置。基础主题和字体修改随商业版提供，部分高级主题包额外付费。
10. 安装服务只负责部署。安装服务范围限定为环境检查、代码部署、初始安装、基础访问验证；不默认包含数据迁移、主题定制、域名解析、SSL 证书购买或长期排障。

### 10.2 已确认技术决策

1. SQLite 足够覆盖第一版全部功能，作为默认数据库。
2. 图片处理优先使用 GD，降低服务器环境门槛。
3. Docker Compose 作为首发推荐部署方式。
4. 第一版不兼容无命令行环境，购买者服务器需要具备命令行或面板终端能力。
5. 主题系统采用模板覆盖方式。
6. 源码完整性检查只校验核心文件，不校验主题包、用户上传文件、配置文件、日志文件和数据库文件。

### 10.3 仍需法务或运营确认

1. 商业授权条款，尤其是禁止二次修改源码、禁止转售、禁止二次分发的边界。
2. 隐私政策，说明情侣数据、照片、私密文件、AI 配置等由购买者自托管保存。
3. 第三方素材授权，包括图标、字体、示例图片、主题素材和商品图片。
4. AI 服务商条款，说明用户自行配置第三方 API Key 时的数据流向和责任边界。
5. 售后范围与退款规则，包括安装失败、服务器环境不满足、用户自行改动导致故障等场景。
6. 付费主题包价格、安装服务价格和主题定制报价规则。

## 11. 建议开发顺序

建议按以下顺序推进：

1. 安装状态与安装向导。
2. 安全配置写入与账号初始化。
3. SQLite 数据层和迁移工具。
4. 后台管理基础框架。
5. 备份恢复。
6. 授权信息。
7. 移动端优化。
8. 交付包与部署文档。

这个顺序的好处是先把“能卖、能装、能配置”的底座做出来，再逐步增强体验和商业能力。
