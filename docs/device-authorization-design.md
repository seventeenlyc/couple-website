# 授权浏览器访问控制设计

日期：2026-09-05  
状态：历史设计稿。2026-09-05 已按用户后续确认的简化规则实施上线，当前行为以 `device-authorization-operations.md` 为准。

后续确认覆盖本文原始方案：各账号首次成功登录自动绑定浏览器；只有“拾柒”是管理员；不再使用首次绑定码。新设备通过管理员核对码审批，授权数据保存在站外；服务器恢复命令重新开放指定账号的首次绑定。下文保留为原始设计记录，不代表所有原始设想都已实施。

## 1. 目标与安全边界

即使域名、双方称呼和登录密码被他人获知，未取得授权浏览器凭证的访问者也不能建立登录会话、读取网站内容或通过文件直链读取照片。公开页面只包含通用验证界面，不显示真实称呼、头像、照片、纪念日期或其他私密信息。

授权对象是浏览器配置文件，不是物理硬件。同一手机的不同浏览器分别授权；清除网站 Cookie、换浏览器或使用新的无痕窗口后需要重新授权。设备名、系统、浏览器版本和 IP 仅供人判断，不能作为放行依据。

授权凭证由服务器生成高强度随机秘密。如果攻击者控制已授权浏览器、复制其凭证，或者取得服务器控制权，本方案不能保证阻止访问。撤销授权可以阻断后续请求，但不能收回已经下载的内容。硬件密钥、客户端证书和 Passkey 不纳入本次实施。

## 2. 已确认的现状

## 3. 采用的方案与其他选择

采用服务器保存的浏览器白名单与 HttpOnly 随机凭证，配合已授权浏览器审批新浏览器。它适合现有 PHP 网站，不需要安装客户端。

单独使用 IP、User-Agent 或设备指纹容易误判和伪造，不采用。设备证书或硬件密钥的绑定能力更强，但增加手机配置和恢复成本，留待确有物理设备绑定需求时单独设计。

## 4. 用户流程

### 首次绑定

1. 部署时不把现有登录会话自动认定为可信设备，也不允许“第一个访问者自动成为管理员”。
2. 管理员通过服务器命令，为指定成员生成一次性绑定码；有效期 15 分钟，使用后立即作废。绑定码至少包含 128 位随机熵，不放入 URL。
3. 成员在自己的浏览器输入绑定码，绑定对应身份。初始绑定仍校验该站点当时使用的登录凭据。
4. 双方分别完成首次绑定。服务器命令可分别补发，补发使同一成员旧的未使用绑定码失效。
5. 后续正常登录仍使用现有登录凭据，并同时验证浏览器授权。

### 新浏览器申请与审批

1. 新浏览器输入登录凭据和自定义设备备注；凭据正确后只建立有效期 10 分钟的待授权状态，不建立业务登录会话。
2. 页面显示核对码和等待状态。核对码用于双方当面或通过已有可信沟通渠道核对，不是授权秘密。
3. 任一成员的已授权且已登录浏览器，可在“安全与设备”查看申请，包括申请身份、备注、浏览器摘要、时间和辅助 IP 信息。
4. 审批者必须输入新浏览器显示的核对码，再明确批准。页面提示备注和设备信息由申请方提供，不能仅凭名称认人。
5. 批准只绑定申请所对应的浏览器秘密，不把该秘密返回给审批者；新浏览器凭自己的待授权秘密领取授权凭证。领取操作原子地消费批准结果，仅可领取一次。
6. 等待页每 5 秒查询一次；过期、拒绝或尝试超限后结束等待。仅持有待授权秘密的浏览器可查询自己的状态。
7. 已授权浏览器可以为双方批准新浏览器，但一条授权只允许登录该授权所属成员。审批权不会解锁另一方的私密空间。

### 查看和撤销

- “安全与设备”列出双方授权记录、所属成员、备注、授权时间、最近使用时间和是否当前浏览器。
- 任一成员的已授权且已登录浏览器可撤销授权，包括自己的当前浏览器；撤销当前浏览器需二次确认，随后退出。
- 每次受保护请求都查验授权状态，撤销后无需等待原有会话过期。已经开始传输的响应不承诺中途撤回。
- 普通退出只结束登录会话，保留浏览器授权；“移除此浏览器”同时撤销授权、删除浏览器凭证并结束会话。

### 恢复

- 清除 Cookie 或更换浏览器后，由其他已授权浏览器审批。
- 所有授权浏览器均不可用时，通过服务器命令生成新的首次绑定码。恢复入口不对公网提供，也不能仅凭双方称呼恢复。
- 授权凭证默认有效 180 天；到期需要重新批准，不根据设备指纹自动恢复。

## 5. 服务端凭证与状态

持久 Cookie 名称为 `__Host-couple_device`，内容为随机记录标识与 256 位随机秘密。设置 `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`，不设置 Domain；仅在 HTTPS 下使用，不存入 localStorage。跨站进入时若首次请求未携带 Cookie，展示通用入口并进行同站重新验证，不立即删除授权。

服务器只存秘密的 SHA-256 摘要，使用恒定时间比较；高熵随机秘密不使用用户自选短密码。首次绑定码、待授权秘密同样只保存摘要。登录成功时更新会话 ID，会话记录授权 ID 和所属身份；授权凭证本身不能替代身份登录步骤。

授权记录字段：随机 ID、成员 ID、秘密摘要、状态、备注、创建时间、失效时间、授权者、撤销时间、最近使用时间、浏览器摘要。IP 和摘要不参与凭证计算；最近使用时间最多每 5 分钟写入一次。

申请状态：`pending → approved → consumed`，或进入 `denied / expired`。设备状态：`active → revoked / expired`。撤销不可通过重放旧申请恢复。所有状态变更在同一个独立锁文件保护下完成读、校验和原子写入，避免并发批准、领取或撤销互相覆盖。

状态数据放在站点根目录之外的专用目录，仅授予 PHP 运行用户必要权限。状态文件丢失、损坏、锁失败或不可读时拒绝放行，不能退回仅称呼登录。

## 6. 访问保护范围

| 入口 | 访问规则 |
| --- | --- |
| 通用登录、绑定、等待页及必要的公共样式脚本 | 可匿名访问，不包含私密配置 |
| 申请、绑定、状态查询接口 | 限流、CSRF/同源校验、对应秘密校验，无业务读取权限 |
| 首页、相册、故事、任务、小铺等页面 | 有效登录会话及有效设备授权 |
| 业务 API | 会话、设备授权、成员权限；写操作额外验证 CSRF |
| 设备管理与审批 | 已授权且已登录，写操作 CSRF 与同源校验，审批额外核对码 |
| 照片、缩略图、头像、故事文件 | 服务端验证会话和设备，不能由静态规则直接放行 |
| 私密空间及私密文件 | 以上全部校验，加私密空间认证及文件归属检查 |
| data、includes、测试、备份、运维脚本 | 公网拒绝访问 |

Nginx 优先采用内部认证子请求保护业务页面与共享上传文件；实施前确认模块支持以及 location 优先级。若当前运行环境不支持，使用 PHP 受控文件入口与内部文件映射完成同样检查。不得以浏览器 JavaScript 跳转代替服务端访问控制。私密文件禁止直接静态读取，保留受控下载接口。

匿名直链请求只返回通用错误或验证入口，不泄漏文件存在性。受保护响应使用 `Cache-Control: private, no-store`，检查 CDN、代理和浏览器缓存；服务器鉴权必须覆盖新请求，不能保证清除已经缓存或下载的旧内容。

## 7. 滥用限制与审计

- 登录和设备申请限流保存在服务端，不能靠更换会话 Cookie 重置。
- 初始默认：每来源 IP 每 15 分钟最多 10 次失败；每个成员最多 5 条有效待审批申请，全站最多 20 条。以实际业务负载调整，不采用持久账号硬锁以免被恶意锁死。
- 每条申请最多 5 次核对码验证失败，超限作废；记录核对失败，不记录核对码。
- 公网状态查询不可枚举申请，不返回其他设备或成员信息；不信任任意客户端提供的转发 IP 头。
- 记录授权、拒绝、撤销、恢复和校验异常。审计日志不记录 Cookie、秘密、绑定码、真实密码或完整请求体。
- 过期申请定期清理，审计日志最多保留 30 天且总量上限 20MB，避免新增无限增长日志。
- 登录和授权页面移除不必要的第三方脚本，防止第三方代码参与敏感流程；设备备注输出必须转义。

1. 比对线上相关代码、Nginx 完整配置、私密文件路由和公开配置接口，保留线上既有业务改动。
2. 实现独立设备存储模块、CLI 绑定/恢复工具、会话与登录集成、申请审批接口、通用验证页和设备管理页。
3. 在隔离数据环境验证以下验收项，再生成仅包含相关文件的部署补丁；不会把本地额外密码要求未经迁移直接覆盖线上。
4. 备份将修改的少量代码和站点配置，验证配置语法，准备 CLI 恢复能力与双方绑定码。
5. 在维护窗口启用完整保护，旧会话必须经过设备绑定后重新登录。先验证自己的首台设备，再完成另一方绑定。
6. 从未授权浏览器验证页面、API 和文件直链被拒绝，再验证已授权浏览器正常读取和上传。
7. 若上线异常，使用服务器恢复或受限维护页；不能无提示回退到公网仅称呼放行。部署失败处理须保留网站访问保护。

## 9. 验收标准

1. 凭据正确但无设备凭证：无法登录，也无法读取任何业务 API 或受保护文件。
2. 更改型号、IP 或 User-Agent：不会使未授权浏览器获得访问权；已授权浏览器正常切换网络不会失效。
3. 初始绑定码过期、重复使用、错误成员或猜测失败：均不能绑定；浏览器不持有原申请秘密不能领取批准结果。
4. 审批、领取并发或重复提交：最多成功一次，不产生额外授权或恢复已撤销设备。
5. 撤销后，原 Cookie 和旧会话的下一次受保护请求失败；普通退出不会撤销授权。
6. 跨成员使用授权凭证被拒绝；网站级设备授权不会绕过私密空间密码或文件归属限制。
7. CSRF、伪造来源、申请枚举、路径穿越及直链绕过被拒绝；错误和日志不泄漏秘密。
8. 设备存储丢失、损坏或并发写入异常时拒绝放行，CLI 恢复流程可用。
9. 清除浏览器数据后可重新审批；全部设备丢失后可经服务器恢复。
10. 验证手机与桌面浏览器的绑定、正常登录、审批、撤销、到期、跨站打开和上传下载流程。
