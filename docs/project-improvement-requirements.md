# Couple Website 当前项目完善需求文档

## 1. 文档信息

- 文档版本：v1.0
- 更新日期：2026-08-12
- 适用范围：当前已部署的双人私密网站
- 当前技术：HTML、CSS、JavaScript、PHP、JSON 文件存储
- 目标运行环境：PHP 8.2 及以上、HTTPS、Apache 或 Nginx

## 2. 项目目标

本阶段只完善当前网站本身。现有首页、相册、任务、小铺、故事、悄悄话和私密空间继续作为核心功能，不进行与当前使用无关的大规模平台化改造。

完成后，网站应达到以下状态：

1. 两名成员可以长期、稳定地使用全部功能。
2. 手机、平板和桌面浏览器都有完整且顺畅的体验。
3. 登录、上传、私密数据和接口调用具备清晰的安全边界。
4. 写入失败、网络中断、重复提交和数据损坏不会悄悄造成不可恢复的问题。
5. 部署、配置、备份、恢复和排错有明确流程。
6. 关键业务流程有自动化测试，发布前可以重复验证。

“完善”不以堆叠功能为标准，而以核心流程完整、异常可恢复、界面一致、数据可信和维护简单为标准。

## 3. 用户与使用场景

### 3.1 用户范围

网站固定服务两名成员。两人拥有独立登录身份、各自头像和积分，并能看到共同内容。私密空间在网站登录之外保留第二层验证。

### 3.2 核心使用场景

1. 登录后查看恋爱时长、纪念日提醒、今日任务和最新照片。
2. 在相册中建立文件夹、上传多张照片、添加标签、移动和删除照片。
3. 每日签到、完成任务、由另一方确认并正确结算积分。
4. 使用积分兑换物品，查看订单、背包和待确认事项。
5. 发送与读取悄悄话，并在已读后正确更新状态。
6. 浏览共同故事时间线，添加和管理手动事件。
7. 通过独立密码进入私密空间，管理私密笔记和文件。

## 4. 当前阶段范围

### 4.1 必须完成

1. 统一配置格式并兼容现有配置。
2. 完成 PHP 8.2 兼容性修复和运行检查。
3. 统一 API 请求、响应、鉴权、CSRF 和错误处理。
4. 加固登录、会话、文件上传、私密文件访问和输出转义。
5. 加固 JSON 数据的锁、原子写入、校验、备份和恢复。
6. 修复积分、任务、签到、购买等跨数据操作的一致性问题。
7. 补齐所有页面的加载、空数据、错误、提交中和成功状态。
8. 完成主要手机尺寸的响应式布局与触控优化。
9. 优化图片尺寸、缩略图、缓存和页面加载性能。
10. 增加部署检查、健康检查、日志规范和备份脚本。
11. 为关键辅助函数、API 和用户流程补充测试。
12. 重写 README，使实际配置和部署方式与代码一致。

### 4.2 暂不实施

1. 原生 iOS 或 Android 应用。
2. 多站点、多租户或多人组织体系。
3. 大规模数据库迁移。
4. 复杂的内容管理后台。
5. 与当前双人使用场景无关的账号角色体系。

## 5. 全局体验要求

### 5.1 页面状态

每个异步区域必须有以下状态：

- 首次加载状态。
- 空数据状态。
- 网络或服务错误状态。
- 提交进行中状态。
- 提交成功状态。
- 可操作的重试入口。

同一个操作在各页面使用统一的提示组件，不依赖浏览器原生 `alert` 作为主要反馈。

### 5.2 导航与登录状态

1. 未登录访问业务页面时跳转到登录页。
2. 会话过期时保留当前页面地址，重新登录后返回原页面。
3. 所有业务页面都能明确返回首页或进入其他主要功能。
4. 退出登录使用受保护的 POST 请求，退出后旧会话立即失效。
5. 私密空间退出不影响网站主会话，网站退出同时清除私密空间状态。

### 5.3 响应式体验

1. 支持宽度 360px 及以上的常见手机浏览器。
2. 触控按钮可点击区域不小于 44px × 44px。
3. 表单聚焦后不被虚拟键盘遮挡，弹窗可滚动并可关闭。
4. 相册、商品、任务和时间线在窄屏不出现横向溢出。
5. 页面不依赖悬停才能完成关键操作。
6. 尊重系统的减少动态效果设置。

### 5.4 可访问性

1. 表单控件具有可读标签和明确错误提示。
2. 图片有有效替代文本，纯装饰图片使用空替代文本。
3. 键盘可以完成登录、导航、弹窗确认和表单提交。
4. 焦点样式可见，弹窗打开时焦点不会跑到背景页面。
5. 文字与背景对比度满足常见可读性要求。

## 6. 页面功能需求

### 6.1 登录页

1. 登录对象、双方身份和密码均进行服务端校验。
2. 连续失败触发渐进式限制，并显示可理解的剩余等待时间。
3. 登录成功后重新生成会话 ID。
4. 配置缺失或配置错误时显示安全、可排查的提示，不输出服务器路径。
5. 登录按钮提交期间不可重复点击，网络失败后允许重试。

### 6.2 首页

1. 恋爱开始日期只使用一个规范配置字段，旧字段自动兼容。
2. 恋爱时长、生日和纪念日按站点时区计算，跨年与闰年结果正确。
3. 每日文案在 AI 服务不可用时使用本地内容，并明确区分加载失败与正常回退。
4. 最新照片、今日任务和未读悄悄话互不阻塞；单个模块失败不影响其他模块。
5. 头像和首页照片上传使用统一上传流程，支持进度、失败提示和重试。

### 6.3 相册

1. 新建、重命名、删除和浏览文件夹时路径始终受控。
2. 上传前显示目标文件夹、文件数量、允许格式和大小限制。
3. 多文件上传保留每个文件的独立进度与结果，单个失败不清空成功项。
4. 标签按用户输入正确拆分、去重、去空格并限制长度和数量。
5. 移动照片后文件路径、文件夹统计和页面显示保持一致。
6. 删除照片前二次确认；删除数据失败时不删除磁盘文件，反之亦然。
7. 大图使用缩略图列表和按需原图查看，减少首屏流量。

### 6.4 任务与签到

1. 每人每天只能成功签到一次，重复请求返回同一结果而非重复加分。
2. 任务状态只允许按“待完成、待确认、已确认”的合法顺序变化。
3. 完成者不能代替确认者确认需要双方确认的任务。
4. 任务确认和积分发放作为一个完整操作处理，任一环节失败都不留下半完成状态。
5. 页面刷新或重复点击不会重复发放奖励。
6. 今日任务生成具有稳定规则，同一天不会因重复请求改变。

### 6.5 小铺

1. 商品列表、筛选、兑换、订单和背包状态保持一致。
2. 购买时校验商品状态、库存、价格和余额。
3. 扣除积分、减少库存、生成订单和生成虚拟物品必须一起成功或一起失败。
4. 重复提交同一购买请求不会生成重复订单。
5. 虚拟物品使用与确认具有明确的操作者和状态限制。
6. 只有满足订单条件的成员可以评价，重复评价按既定规则处理。

### 6.6 故事时间线

1. 系统事件、照片事件和手动事件按统一时间规则排序。
2. 手动事件支持新增和删除，输入标题、内容和日期都有长度及范围校验。
3. 删除仅作用于手动事件，不允许伪造 ID 删除系统生成事件。
4. 时间线数据异常时跳过单条坏数据并记录日志，不导致整页空白。
5. 手机端时间线、图片和长文本保持清晰可读。

### 6.7 悄悄话

1. 只能向当前登录成员的另一方发送消息。
2. 消息内容去除首尾空白并限制长度，空消息不可提交。
3. 已读操作只允许接收者执行，重复标记已读是安全的。
4. 首页未读提示与实际未读数量一致。
5. 输出内容使用文本方式渲染，不执行用户输入的 HTML。

### 6.8 私密空间

1. 私密密码和登录密码独立验证，使用安全哈希保存。
2. 连续验证失败触发限制，私密会话在一段时间无操作后失效。
3. 私密笔记标题和正文具有长度限制，展示时不执行 HTML。
4. 私密文件不能通过真实路径直接访问，只能通过鉴权下载接口读取。
5. 上传、下载和删除均校验当前用户、私密会话和 CSRF。
6. 删除操作同时保证元数据与磁盘文件一致。

## 7. 安全要求

### 7.1 登录与会话

1. 新配置只接受 `password_hash()` 生成的密码哈希；旧明文配置仅保留一次性迁移兼容提示。
2. Cookie 使用 `HttpOnly`、`SameSite=Lax`，HTTPS 下启用 `Secure`。
3. 登录成功、权限变化和退出时轮换或销毁会话。
4. 会话具有空闲超时和绝对有效期。
5. 登录限制记录不保存明文密码或完整敏感标识。

### 7.2 请求与输出

1. 所有写操作只接受规定的 HTTP 方法并验证 CSRF。
2. JSON、表单和文件上传使用同一套请求校验规则。
3. API 输出统一设置 JSON 类型、状态码和安全错误结构。
4. 用户输入默认按纯文本渲染；需要 HTML 的位置使用严格白名单。
5. 生产环境不向客户端返回堆栈、绝对路径、密钥或原始异常。

### 7.3 文件与路径

1. 使用服务端 `finfo` 判断 MIME，不信任客户端文件名和类型。
2. 图片只允许 JPEG、PNG、WebP，使用 GD 重新编码后保存。
3. 文件名由服务端随机生成，原文件名仅作为经过清理的展示信息。
4. 上传目录禁止执行 PHP、HTML、SVG 和脚本文件。
5. 所有移动、读取和删除操作验证解析后的真实路径位于允许目录内。
6. 上传大小、图片像素、文件数量和请求体大小均有限制。

### 7.4 服务端保护

1. `data/`、日志、备份和配置不可通过 Web 直接访问。
2. 默认返回 `X-Content-Type-Options`、`Referrer-Policy`、`Content-Security-Policy` 等安全响应头。
3. AI 密钥优先从服务器环境变量读取，不返回前端、不写入日志。
4. 健康检查只返回必要状态，不暴露版本、路径和配置内容。

## 8. 数据可靠性要求

当前阶段继续使用 JSON 文件，但所有读写必须通过统一数据访问函数。

1. 读改写操作在同一独占锁内完成，避免并发请求互相覆盖。
2. 写入临时文件后执行校验，再以原子替换方式更新主文件。
3. 关键写入保留最近可用备份，备份失败时记录并阻止高风险操作继续。
4. 跨多个文件的积分、订单、任务操作使用统一事务锁和回滚快照。
5. 每类 JSON 数据在读取和写入时校验必要字段、类型、唯一 ID 和状态值。
6. 发现主文件损坏时只从已验证备份恢复，并记录恢复事件。
7. 所有时间使用带时区的标准格式，ID 使用不可预测的随机值。
8. 提供只读检查命令、完整备份命令和明确的恢复命令。

## 9. 性能与稳定性要求

1. 首页各模块并行加载，单个慢接口不阻塞整页。
2. AI 请求设置连接与总超时，并使用按日期缓存和本地回退。
3. 相册列表只加载缩略图，原图按需加载并设置合理缓存头。
4. 图片上传限制总像素，生成缩略图时控制内存占用。
5. 重复请求、超时重试和页面刷新不重复执行有副作用的操作。
6. API 为每次请求生成请求 ID，错误日志可以据此定位。
7. 日志按日期或大小轮换，不无限增长。
8. 页面运行所需的样式、字体、图标和装饰图片由本站提供，不把外部 CDN 作为页面可用的前提。

## 10. 配置与部署要求

1. 规范配置使用 `site.start_date`，读取时兼容旧 `startDate`。
2. 示例配置不包含可直接使用的弱密码或真实密钥。
3. 启动检查验证 PHP 版本、必需扩展、目录权限、配置格式和 HTTPS 状态。
4. 必需扩展为 `json`、`mbstring`、`fileinfo`、`gd`；AI 功能需要 `curl`。
5. `data/` 和 `uploads/` 仅授予 Web 进程所需最小权限，不使用 `777`。
6. README 分别给出 Apache、Nginx 和 PHP 本地开发启动说明。
7. 部署更新前必须备份 `data/` 和 `uploads/`，更新后运行健康检查。

## 11. 日志与排错要求

应记录：

- 登录成功、失败和限制触发。
- 配置缺失或格式错误。
- JSON 写入、校验、恢复和回滚失败。
- 上传拒绝、图片处理失败和越界路径请求。
- AI 服务超时和回退原因。
- 积分、任务、订单等关键业务操作失败。

日志不得记录密码、私密笔记正文、悄悄话正文、文件内容和完整 API 密钥。

## 12. 测试要求

### 12.1 PHP 单元测试

覆盖配置兼容、密码校验、路径约束、JSON 原子写入、锁、标签处理、日期计算、任务状态、积分和订单规则。

### 12.2 API 集成测试

覆盖未登录、方法错误、CSRF 错误、非法输入、成功请求、重复提交、文件过大、伪造 MIME 和数据写入失败。

### 12.3 浏览器流程测试

覆盖登录、首页加载、相册上传与移动、签到与任务、小铺兑换、悄悄话、故事事件和私密空间。

### 12.4 兼容性测试

至少验证最新稳定版 Chrome、Edge、Safari 移动端尺寸，以及 360px、390px、768px、1440px 四组视口。

## 13. 验收标准

发布候选版本必须同时满足：

1. 所有 PHP 文件通过 PHP 8.2 语法检查。
2. 自动化测试全部通过，关键流程无未处理异常。
3. 所有写接口都具有登录校验、方法校验和 CSRF 校验。
4. 上传目录无法执行脚本，私密文件无法通过直链访问。
5. 连续并发执行签到、确认任务和购买时不发生重复奖励或负余额。
6. 模拟 JSON 损坏后可以从有效备份恢复。
7. 手机和桌面主要页面无横向溢出、遮挡和不可点击控件。
8. AI 服务不可用时首页仍能正常使用。
9. 部署文档能在干净环境中完成配置、启动、备份和恢复。
10. 发布前安全检查和浏览器回归清单全部完成。

## 14. 实施顺序

1. 建立测试基线和备份，固定现有可用行为。
2. 统一配置、启动流程、API 响应和请求客户端。
3. 完成登录、会话、上传、路径和输出安全加固。
4. 完成 JSON 锁、原子更新和跨文件业务一致性改造。
5. 逐页补齐功能状态、错误恢复和移动端体验。
6. 完成图片性能、AI 回退、日志和部署维护能力。
7. 执行完整回归、安全检查和真实服务器验证。

## 15. 完成定义

本阶段只有在“正常使用顺畅、异常情况可解释、关键数据可恢复、部署过程可重复、主要流程可自动验证”五项同时满足时才算完成。后续方向在此版本稳定运行后再单独评估，不提前混入当前实施范围。
